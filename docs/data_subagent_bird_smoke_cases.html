先讲清楚：这里的 Wren context layer 是谁生成的？

对 BIRD SQLite 数据库这条线，当前不是 WrenAI 自己从 SQLite 自动推理出完整业务 MDL。 当前 WrenAI CLI 的 `context import` 主要支持 dbt，不支持直接把任意 SQLite 数据库自动导入成业务语义层。

所以我们做了一个最小转换器：读取 BIRD SQLite schema，把表、字段、基础类型、部分 foreign key 转成 Wren project 文件； 再把 SQLite 数据复制成 DuckDB，让 WrenAI CLI 读取这个 Wren project，并执行 `context validate/build`、`dry-plan`、`dry-run`、`query`。

换句话说：context 文件是我们脚本生成并写入 `data/wren/bird_debit_card_specializing_wren_project/` 的； 但后续读取 context、展开 SQL、验证 SQL、执行查询的是实际安装的 WrenAI CLI，不是 mock。

案例 2：runtime 成功但 needs_triage

eval_id: bird_debit_card_specializing_0003 trace_9e4f4e17a9c04474bda41a7ab49aa190 review_status: needs_triage

问题

What was the average monthly consumption of customers in SME for the year 2013?

Evidence:
Average Monthly consumption = AVG(Consumption) / 12
Year 2013 can be presented as Between 201301 And 201312

链路阶段输出

1. Wren context 获取 
used models:
  customers(CustomerID, Segment)
  yearmonth(CustomerID, Date, Consumption)
2. DeepSeek generate_sql 
SELECT AVG(ym.Consumption)
FROM yearmonth ym
JOIN customers c ON ym.CustomerID = c.CustomerID
WHERE c.Segment = 'SME'
  AND ym.Date BETWEEN '201301' AND '201312'
3. Guardrail / Wren dry-plan / Wren dry-run 
guardrail: pass
dry-plan: pass
dry-run: OK
4. Wren execute / 结果总结 
rows: [{"avg(ym.Consumption)": 5519.4751714451}]
answer: 5519.4751714451
5. Gold SQL 
SELECT AVG(T2.Consumption) / 12
FROM customers AS T1
INNER JOIN yearmonth AS T2 ON T1.CustomerID = T2.CustomerID
WHERE SUBSTR(T2.Date, 1, 4) = '2013'
  AND T1.Segment = 'SME'
6. Gold 对比 
predicted result: 5519.475171445075
gold equivalent result: 459.9562642870896
execution_match: false
review_status: needs_triage
初步归因：DeepSeek 生成的 SQL 没有执行 evidence 中的 `/ 12`。这更像“业务 evidence 遵循不足”， 但仍要人工确认 gold 的业务定义是否合理，不能只按单个 gold mismatch 盲目改 prompt。

Which year recorded the most consumption of gas paid in CZK?

4. Gold SQL 可执行 
SELECT SUBSTR(T2.Date, 1, 4)
FROM customers AS T1
INNER JOIN yearmonth AS T2 ON T1.CustomerID = T2.CustomerID
WHERE T1.Currency = 'CZK'
GROUP BY SUBSTR(T2.Date, 1, 4)
ORDER BY SUM(T2.Consumption) DESC
LIMIT 1
5. Gold 结果 
gold result: 2013
初步归因：这不是 Wren dry-run 失败，也不是数据库不可执行，而是 LLM 返回空响应导致 SQL 生成阶段失败。 下一步应增加 SQL generation 的 retry/backoff，并记录 raw response 便于追踪。

当前结论

BIRD 这条线已经验证了真实 WrenAI CLI 能读取我们生成的 Wren project，并完成 dry-plan、dry-run、execute。 但这个 context layer 目前只是 schema-level 最小语义层，还不是高质量业务语义层。

下一步不应该只改 prompt。更合理的是先修 relationship 生成 bug，再把 BIRD evidence 和高频 gold SQL 模式沉淀成 Wren knowledge/rules/examples，最后再跑 smoke5 和 30-case 回归。
