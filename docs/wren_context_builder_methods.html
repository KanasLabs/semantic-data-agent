WrenAI Context Layer / MDL 构建方法整理

本文整理当前项目已核对的 WrenAI 构建 context layer / MDL 的几种路径， 重点区分“WrenAI core 内部原生导入”和“agent/script 按 Wren workflow 生成 YAML 后交给 Wren 校验编译”。

本地核对版本：wrenai 0.12.0。日期：2026-07-09。

一句话结论

WrenAI 支持多种方式进入 MDL/context layer，但当前本地已验证的 OSS CLI 并没有一个 wren context import database 式的通用命令， 可以对任意数据库自动解析并生成高质量业务语义层。

dbt 是 WrenAI 原生 import 路径； 已有 MDL/OSI 可以由 WrenAI 原生 ingest/build； 普通数据库 通常由人、Codex、Claude Code 或脚本先做 schema introspection 和 YAML 生成， 再交给 WrenAI 做 validate/build/dry-run/query。 

dbt project
  -> WrenAI native context/profile import
  -> validate/build/query

existing MDL / OSI
  -> WrenAI native init/build from file
  -> validate/build/query

ordinary database
  -> agent/script inspects schema and writes Wren YAML
  -> WrenAI validate/build/dry-run/query

dlt/SaaS path
  -> dlt loads data to DuckDB
  -> bundled skill script introspects DuckDB and writes Wren YAML
  -> WrenAI validate/build/query

方法总览

方法 谁解析输入 谁生成 Wren context / MDL 文件 WrenAI 负责什么 适用场景 关键限制
1. dbt 原生导入 WrenAI CLI 读取 dbt project、manifest、catalog、profiles WrenAI CLI context import dbt、profile import dbt、validate/build 已有 dbt 工程和 dbt 语义资产 本地 CLI import source 当前只支持 dbt
2. 已有 MDL / OSI 输入 WrenAI CLI 读取已有 MDL JSON 或 OSI YAML 已有文件提供，或由 Wren 从 OSI/MDL 转换 context init --from-mdl、--from-osi、build --from-osi 已有 semantic model 标准文件或迁移场景 不是数据库 introspection，前提是语义模型已经存在
3. 手写或普通 agent 生成 Wren YAML 人、Codex、Claude Code、业务脚本、数据库 driver 人或 agent/script 项目 scaffold、类型归一化工具、validate/build/dry-run/query 任意数据库、业务定制、渐进式建模 流程质量取决于人或脚本，容易漏校验、误猜类型或关系
4. generate-mdl skill agent 按 Wren 官方 workflow 使用 SQLAlchemy、driver 或 SQL 探索数据库 agent 按 skill 规则写 Wren YAML 提供官方 agent 操作规程、类型归一化、validate/build/query 让 Codex/Claude Code 等 agent 系统化 onboarding 普通数据库 仍然是 agent/script 执行 introspection，不是 Wren core 一条命令自动解析任意 DB
5. dlt-connector skill + script dlt pipeline 和 bundled introspect_dlt.py 脚本 skill 附带脚本生成 Wren project 后续 validate/build/query HubSpot、Stripe、Salesforce、GitHub、Slack 等 SaaS 数据经 dlt 落 DuckDB 偏 SaaS/dlt 路径，不是通用数据库原生 import

方法 3 和方法 4 的差别

方法 3：手写或普通 agent 生成 YAML

这是能力层面：只要知道 Wren project 文件结构，就可以由人或脚本直接写 wren_project.yml、models/*/metadata.yml、 relationships.yml 和 knowledge 文件。

它可以很灵活，但流程规范完全取决于实现者。比如是否读取真实 schema、 是否做类型归一化、是否确认 foreign key、是否运行 validate/build，都没有默认约束。

方法 4：generate-mdl skill

这是流程层面：WrenAI 官方把普通数据库 onboarding 拆成 agent workflow， 指导 agent 如何检测项目、连接数据库、发现表字段、归一化类型、写模型和关系、 validate/build，并做 smoke query。

它的产物仍然是 Wren YAML，但比“随便让 agent 写”多了操作规程和防错约束， 适合被我们固化成可重复的 Context Builder CLI。

维度 手写 / 普通 agent generate-mdl skill
流程来源 我们自己设计或人临场判断 Wren 官方 skill 给出的 agent workflow
schema 发现 可以随便用 SQL、driver、手工整理 明确建议 SQLAlchemy、database driver、raw SQL / information_schema
类型处理 可能手写映射 推荐 wren.type_mapping.parse_type 或 wren utils parse-type
关系处理 自己决定是否推断 从 FK 约束发现，不确定时确认，避免静默错误 join
校验 可能漏掉 明确要求 wren context validate、wren context build、smoke query
本项目位置 早期 BIRD/SQLite 脚本属于这一类 Context Builder 的目标是把这个官方 workflow 产品化

当前本地验证

本地 wrenai 0.12.0 的 context import 和 profile import 都明确写着 import source 当前是 dbt。 本地源码中，非 dbt source 会直接返回 unsupported。 

.\.venv-wren\Scripts\wren.exe context import --help
# Import source (currently: dbt)

.\.venv-wren\Scripts\wren.exe profile import --help
# Import source (currently: dbt)

.\.venv-wren\Scripts\wren.exe context init --help
# supports --from-mdl and --from-osi

.\.venv-wren\Scripts\wren.exe skills get generate-mdl
# agent workflow for database schema discovery and Wren YAML generation

我们当前实现属于哪一种

当前 src/data_subagent_context_builder/ 已调整为 方法 4：generate-mdl skill 优先。它仍然不是 WrenAI core 一条命令自动解析数据库，但 MDL authoring 默认交给 Codex/agent 按 Wren 官方 skill 执行。 

SQLite database
  -> Context Builder inspects factual schema only
  -> Context Builder converts data to DuckDB runtime
  -> WrenAI context init --empty scaffolds project
  -> Context Builder writes onboarding/schema_manifest.json
  -> Codex reads Wren generate-mdl skill
  -> Codex writes or updates Wren YAML project
  -> WrenAI context validate/build/dry-run
  -> onboarding report / smoke eval

原来的确定性 SQLite YAML 生成已降级为 generate-schema-draft / generate-from-db --mode draft fallback。它适合 smoke/debug bootstrap， 不再是推荐的 semantic layer 生成路径。

术语边界

WrenAI core 做的事

profile MDL format validate build dry-plan dry-run query

WrenAI 是语义层格式、校验、编译和执行底座。它也提供 dbt import、 MDL/OSI ingest、type mapping、skills、memory 等能力。

agent/script 做的事

schema introspection YAML generation relationship inference report

对普通数据库，agent/script 通常负责探索表、字段、类型、主外键和样例查询， 然后写 Wren YAML。WrenAI 再接管校验、编译和查询。
